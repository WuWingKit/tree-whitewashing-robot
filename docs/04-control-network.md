# 控制分工与网络

## 当前选型

F407ZGT6负责四轮编码器采样、速度闭环、滑台步进脉冲、舵机命令、测距、限位、急停、泵与搅拌联锁。电脑输出任务和速度设定，不能通过无线逐个发送实时PWM或每个步进脉冲。

单块ESP32-S3 N16R8负责Wi-Fi、USB Host相机采集和数据转发，与F407通过3.3V串口交互。S3主要转发压缩图像，不承担完整视觉算法。电脑接收图像和状态，执行树干识别、接近规划、可见涂白评价及界面。

可以应用层同时上行图像/状态、下行指令；无线共享空口与CPU/内存仍存在竞争，不能因此承诺无延迟或物理全双工。

## USB和双相机的可实施性边界

已购USB相机：720P90°一台，720P70°一台；已购Type-C输入Hub。两个开发板USB插座不是两个相机Host：原生USB使用GPIO19/20，另一口连接USB转UART芯片。

S3 USB Host为Full Speed，速率12Mbit/s；有效吞吐低于总线标称速率。16MB Flash/8MB PSRAM改善存储和缓存，不提升USB带宽。依据：[乐鑫USB Host官方说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/usb_host.html)。

必须读取相机UVC描述符，核对Full Speed下可用分辨率、MJPEG格式、端点与带宽，再选择ESP-IDF及对应USB/UVC组件版本。PC端能开720P不代表S3上也能开相同档位。两台连接Hub时还需验证Host库及UVC驱动多设备/切换支持，不能只凭USB口形状确认。

初始采用分时：行驶时前相机，停车喷涂/评价时作业相机。若停止一台视频流仍无法稳定接另一台，要进一步验证设备释放、重新枚举或受控USB切换；不承诺仅关闭PC窗口就能释放总线。先用低分辨率和低帧率打通，再上调。

如果单相机都无法满足，优先换已验证兼容的相机或采集方案；若双机兼容失败，可评估分立采集节点或能运行Linux的车载主机。这是备选，不列为当前已购架构。

## 具体开发板的USB供电

所附S3原理图标题ESP32-S3-COREBOARD V1.4，USB1连CH343P，USB2连原生USB。网店示意CH340C与资料芯片不同，应确认到货版本。

图中原生Type-C的CC带5.1k下拉，且存在USB-OTG与IN-OUT零欧连接配置。这种接法不能仅凭“OTG”字样就认定可给Type-C Hub正确提供Host角色与VBUS。需核实跳线、线缆、CC和5V电源路径，必要时使用正确Host供电转接，避免多电源反灌。Hub下游Type-C接口是否有数据通道也未确认。

## 网络设计草案

首轮使用近距离已有2.4GHz局域网，电脑和S3接同一网络；也可测试S3热点。无需因为要联网就再次给F407单独配Wi-Fi。天线不能被电池、金属立柱和液体容器遮挡，实际距离和丢包要测。

图像可采用MJPEG/HTTP；控制采用独立TCP连接并设置长度、序号、超时、确认和重连。采用最新帧优先、有界队列，网络拥塞时丢弃旧图，不让大图像发送阻塞控制心跳。实际协议尚未实现。

F407→S3状态包含测距值及有效性、编码器、限位、运行状态和故障；电脑→F407包含速度、停止、回零、开合、升降和任务命令。无需每个设备持续上传全部原始信号，但保留查询和操控接口。默认面向本地局域网，云端可作记录或后续规划，不作为停车保护依赖。
